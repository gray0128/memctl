# 记忆内容规范

## 保存范围

- 跨会话仍然成立的事实：用户偏好、人物与项目、命名约定、环境约束、已解决的问题和可复用步骤。
- 保存前确认它不是临时状态。一次性任务进度、当前分支、临时路径与本次会话的中间结论不保存。
- 涉及第三方个人信息或无法判断是否敏感时，先询问用户。

## 禁止保存

- 密钥、令牌、密码、私钥、cookie，以及连接串中的凭据。
- 原始日志、大段构建输出、完整对话记录。
- 用户明确要求删除或不要保留的内容。

## 条目格式

- 一行一条 bullet：`- <事实> [source: <tag>; added: YYYY-MM-DD]`。
- 事实写成可独立理解的单句，不换行，不以「见上」等指代承接上下文。
- `source` 使用上下文给出的来源标签 `agent://<device>/<agent>/<sid>`；没有标签时省略或询问用户，不编造。
- `added` 记录学到该事实的日期，格式 `YYYY-MM-DD`。
- 同一行可以有多个 `[source: ...]`，分别保留；不合并、不重排。
- 保留已有条目的未知元数据与顺序，不整段重排文件。

## 文件与链接

- `MEMORY.md` 是入口与索引。每个新建文件在其中增加一行 `[[path]]` 与简短说明，保持索引简短。
- 链接使用仓库根相对路径；Markdown 文件省略 `.md`，其他资产保留扩展名。
- 一个事实只写一处。其他文件链接过去，不复制正文。
- 旧条目失效时按事实类型处理，不追加矛盾条目：
  - 状态型（偏好、环境、当前角色、项目现状、命名约定）就地改写或删除，旧值不另存一条。
  - 事件型（为什么这样选、发布、事故、迁移）追加一条带 `added` 的新条目，旧条目原样保留；决策后来被推翻不是错误，不回改旧条目。
- 记忆文件内不维护变更记录，不写「以前是 X，现在是 Y」；历史版本由 Git 保存。
- 保持文件原有标题层级、换行与末尾状态；不做无关的格式化、空格调整或排序。

## 写入前检查

- 读取目标文件与 `MEMORY.md`，确认同一事实没有别处记录。
- 确认修改后的内容仍是单行 bullet，引用的链接目标存在。
- 新增文件后确认 `MEMORY.md` 索引已更新。
- 事实与来源可复核；不把推测写成确定结论。
